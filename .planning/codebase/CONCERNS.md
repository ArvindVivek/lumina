## Tech Debt

### Next.js Configuration Empty

**Issue:** Next.js config file has no meaningful configuration.
- **File:** `next.config.ts` (lines 3-5)
- **Current State:** Empty config object with only a comment placeholder
- **Impact:** Missing potential optimizations, security headers, redirects, or other Next.js features
- **Fix approach:** Add required configuration as features are developed (image optimization, security headers, API routes, etc.)

### Tailwind CSS Version Mismatch Risk

**Issue:** Using new Tailwind CSS v4 with @tailwindcss/postcss which is still in early adoption.
- **Files:** `package.json` (line 17), `postcss.config.mjs` (line 3), `app/globals.css` (line 1)
- **Current State:** Using `@tailwindcss/postcss: ^4` and `tailwindcss: ^4` (latest major version)
- **Impact:** Potential breaking changes with minor updates, limited community support and examples, experimental features may be unstable
- **Fix approach:** Monitor Tailwind CSS v4 releases and test thoroughly with each update; consider version locking if production-ready

### Missing TypeScript Path Configuration Usage

**Issue:** TypeScript path alias defined but not being used in codebase.
- **File:** `tsconfig.json` (lines 21-23) defines `"@/*": ["./*"]`
- **Current State:** Imports in `app/layout.tsx` and `app/page.tsx` use relative paths (e.g., `"./globals.css"`) instead of `@/` alias
- **Impact:** Inconsistent code style, harder to refactor files, reduced code clarity
- **Fix approach:** Standardize imports to use `@/` alias across codebase once structure is finalized

### Global Font Variable Names Unused

**Issue:** Font variables defined but may not be properly applied.
- **File:** `app/layout.tsx` (lines 5-13)
- **Issue:** Font variables `geistSans` and `geistMono` defined with CSS variables but `globals.css` hardcodes Arial/Helvetica fallback
- **Impact:** Font loading optimization may not work as intended, inconsistent font stack
- **Fix approach:** Remove redundant font-family fallback in `globals.css` and rely on configured CSS variables

## Configuration Issues

### Production Readiness Missing

**Issue:** Multiple Next.js and React versions represent leading-edge releases with limited production history.
- **Package versions:** Next.js 16.1.6, React 19.2.3, TypeScript 5.x, ESLint 9.x
- **Current State:** All dependencies use very recent versions that may contain undiscovered issues

## Fragile Areas

### Layout Component Structure

**Issue:** Single layout component handling all root-level rendering.
- **File:** `app/layout.tsx`
- **Why fragile:** Changes to root layout affects entire application; no separation between document structure and content
- **Safe modification:** Extract metadata management into separate file/constants before adding routes; establish component hierarchy
- **Test coverage:** No tests exist; manually verify layout renders correctly with dark mode support

### Type Safety in Layout

**Issue:** React.ReactNode type used for children with Readonly constraint may miss edge cases.
- **File:** `app/layout.tsx` (lines 22-24)
- **Current State:** Uses `Readonly<{ children: React.ReactNode }>` pattern
- **Potential issue:** React 19 component signature changes; readonly constraint may cause issues with future middleware
- **Recommendation:** Verify with React 19 documentation and consider explicit typed children

## Styling Concerns

### CSS Custom Properties Naming

**Issue:** Custom property naming uses non-standard format.
- **File:** `app/globals.css` (lines 3-6)
- **Current State:** Uses `--background` and `--foreground` (double-dash prefix correct, but no namespace)
- **Issue:** Potential naming conflicts if other libraries inject CSS variables
- **Fix approach:** Rename to `--app-background` and `--app-foreground` to avoid conflicts

### Dark Mode Implementation Incomplete

**Issue:** Dark mode media query defined but may not respect system preferences correctly.
- **File:** `app/globals.css` (lines 15-20)
- **Current State:** Uses `@media (prefers-color-scheme: dark)` but no explicit light mode styles
- **Impact:** May not transition smoothly between modes; no option for user preference override
- **Fix approach:** Add explicit next.js theme configuration and user preference toggle when features are added

## Security Considerations

### Metadata XSS Risk

**Issue:** Dynamically generated metadata not yet implemented, but future feature.
- **File:** `app/layout.tsx` (lines 15-18)
- **Recommendation:** When adding dynamic metadata (user input), ensure proper escaping/sanitization
- **Mitigation:** Use Next.js metadata API's built-in escaping; never use innerHTML

### External Link Security

**Issue:** Several external links in page.tsx lack security attributes.
- **File:** `app/page.tsx` (lines 21-22, 29-30, 40-41, 55-56)
- **Current State:** Links have `target="_blank"` and `rel="noopener noreferrer"` but this template may be copied without these attributes
- **Fix approach:** Establish link security guidelines; use a link component wrapper that enforces rel attributes

### No Content Security Policy

**Issue:** No CSP headers defined.
- **Current State:** No next.config.ts headers configuration
- **Impact:** Vulnerable to XSS attacks and code injection
- **Fix approach:** Add CSP headers in next.config.ts as part of security hardening
